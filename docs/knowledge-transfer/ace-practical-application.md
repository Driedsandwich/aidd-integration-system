## 📋 概要

本文書は、**ACE（Agentic Context Engineering）理論を実際のAI駆動開発プロジェクトで適用した実践例**をまとめたものです。

**ACE理論とは**:
- Stanford University、SambaNova Systems、UC Berkeleyによる研究
- LLMのコンテキスト管理における「コンテキスト崩壊」の問題を解決
- 3段階プロセス（Reflect→Generate Delta→Apply）による差分更新

**本プロジェクトでの実践**:
- 約30,000字の大規模文書作成プロジェクト
- 約600行のルールファイル管理
- ACE理論に基づく差分更新の徹底

**効果**:
- コンテキスト崩壊の回避（詳細情報の保持）
- ルールファイルの品質維持
- 効率的なルール更新

## 🎯 Part 1: コンテキスト崩壊の認識

### 問題: Monolithic Rewriting（一括書き換え）

**典型的な失敗**:
```
ユーザー: 「今やった作業内容をルールに追加してください」
AI: （ルールファイル全体を読む → 全体を書き換える）

結果:
- 詳細情報が消失
- 簡潔すぎる要約になる
- 重要な個別情報が失われる
```

**例**:
```
Before（詳細な情報）:
「ツールXにはパラメーターA、B、Cがあり、
 過去に実行した時にパラメーターBを必須と
 認識していなかったため失敗した。
 次回は必ずBを指定すること」

After（一括書き換え後）:
「ツールXを適切に使用する」
← 具体的な失敗情報が消失
```

**影響**:
- ルールの品質低下
- 具体的なガイダンスの喪失
- 同じ失敗を再度繰り返すリスク

## 🎯 Part 2: ACE的アプローチ（3段階プロセス）

### 従来の方法（問題あり）

```
「今やった作業をルールにして」
→ ルールファイル全体を書き換え
→ コンテキスト崩壊
```

---

### ACE的アプローチ（推奨）

#### Step 1: Reflect（振り返り）

**プロンプト例**:
```
「今やった作業を振り返って、
 どこに問題があったか、
 何がうまくいったか分析してください」
```

**出力例**:
```
問題点:
- 数値を推測で記載した
- 実測を怠った

うまくいったこと:
- 即座に誤りを認識
- 実測して修正
```

---

#### Step 2: Generate Delta（差分生成）

**プロンプト例**:
```
「上記の分析結果をもとに、
 ルールのどこをどう書き換えたらいいか、
 変更差分を出してください」
```

**出力例**:
```
ファイル: .cursor/rules/thesis-project.mdc
セクション: 原則1（ハルシネーション回避）
追加内容:

### 数値の徹底検証
- ✅ 数値は必ず実測（コマンド実行結果）
- ✅ 実測時点を併記（例: 「実測: 2025-10-14」）
- ✅ 推測・概算を禁止
```

---

#### Step 3: Apply（差分適用）

**実装**:
- `search_replace` ツールを使用
- 指定されたセクションに差分のみを追加
- ファイル全体の書き換えを避ける

**実践例**:
```typescript
search_replace({
  file_path: ".cursor/rules/thesis-project.mdc",
  old_string: "### 原則1: ハルシネーション回避\n\n**必ず実行**:",
  new_string: "### 原則1: ハルシネーション回避\n\n#### 数値の徹底検証\n- ✅ 数値は必ず実測\n- ✅ 実測時点を併記\n\n**必ず実行**:"
})
```

## 🛠️ 実践ガイド

### ルール更新時のチェックリスト

- [ ] Step 1（Reflect）を実施
- [ ] Step 2（Generate Delta）を実施
- [ ] Step 3（Apply）で差分のみ更新
- [ ] ファイル全体の書き換えを避けた
- [ ] 更新後のルールファイルの行数を確認

### コンテキスト崩壊回避のチェックリスト

- [ ] 詳細情報が保持されているか
- [ ] 具体的な失敗例が残っているか
- [ ] 簡潔すぎる要約になっていないか
- [ ] 重要な個別情報が失われていないか

## 📊 適用場面

### 1. ルールファイルの更新

**適用**:
- 新しい失敗事例が発生した時
- ルールに追加情報を記録する時
- ACE的アプローチ（3段階プロセス）を使用

---

### 2. ドキュメントの更新

**適用**:
- 大規模ドキュメントの部分的な更新
- 差分のみを更新
- 全体の書き換えを避ける

---

### 3. プロジェクト設定の更新

**適用**:
- 設定ファイルの部分的な更新
- 差分のみを変更
- 既存の設定を保持

## 🎓 まとめ

**ACE理論の実践適用3原則**:
1. **3段階プロセス**: Reflect→Generate Delta→Apply
2. **差分のみ更新**: `search_replace` で差分のみ適用
3. **コンテキスト崩壊回避**: 詳細情報を保持、一括書き換えを避ける

**適用タイミング**:
- ルールファイルの更新時
- 大規模ドキュメントの更新時
- プロジェクト設定の更新時

**期待効果**:
- コンテキスト崩壊の回避
- ルールの品質維持
- 効率的な更新
