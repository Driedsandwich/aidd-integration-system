# 並行PR戦略とトークン最適化

**最終更新**: 2025-10-18  
**出典**: 学術文書の協調執筆プロジェクトで実証済みの実践知  
**適用範囲**: 大規模ファイルの段階的開発、複数AIでの協調レビュー

---

## 📋 概要

本文書は、**1つのファイルに対する複数の並行PRを効率的に管理し、トークン消費を最適化する実践的手法**をまとめたものです。

**背景**:
- 約15,700字の大規模ファイルを6つの並行PRで段階的に開発
- 初期のレビュー方針でトークン過剰消費の問題を発見
- 新しいレビュー方針を確立し、トークン消費71%削減を達成

**効果**:
- トークン消費: 71%削減（約34,600字削減）
- レビューの一貫性: 各セクションは1回のみレビュー
- レートリミット制約の緩和: ファクトチェックAIのリソース節約

---

## 🎯 並行PR戦略の利点と問題点

### 利点

**執筆速度の向上**:
- 1つのファイルを複数のセクションに分割
- 各セクションを並行して執筆
- 全体の完成を待たずに段階的にレビュー

**実践例**（大規模ファイル、約15,700字）:
```
PR #1: セクション A を追加（約2,400字）
PR #2: セクション B を追加（約2,200字）
PR #3: セクション C を追加（約2,300字）
PR #4: セクション D を追加（約2,600字）
PR #5: セクション E を追加（約3,700字）
PR #6: セクション F を追加（約2,500字）
```

**効果**:
- 6つのセクションを並行して執筆
- 各セクション完成後、即座にレビュー開始
- 全体の完成を待つ必要なし

---

### 問題点（初期のレビュー方針）

#### 問題1: トークン過剰消費

**状況**:
```
PR #1: セクション A を含む（ファイル全体: A）
PR #2: セクション A + B を含む（ファイル全体: A + B）
PR #3: セクション A + B + C を含む（ファイル全体: A + B + C）
...
PR #6: セクション A-F を含む（ファイル全体: A-F）
```

**問題**:
- セクション A を6回レビュー（PR #1-6）
- セクション B を5回レビュー（PR #2-6）
- ...
- セクション F を1回レビュー（PR #6のみ）

**トークン消費**:
- 合計約48,600字をレビュー（実際のファイルサイズは約15,700字）
- 約3.1倍の無駄なトークン消費

---

#### 問題2: レビュー内容の不一貫性

**状況**:
- 同じセクション A に対して、PR #1, #2, #3 で異なるレビューコメント
- PR #1で「問題なし」、PR #3で「修正すべき」等の矛盾

**影響**:
- レビュー者の混乱
- 執筆者の混乱（どの指摘に従うべきか）
- レビューの信頼性低下

---

#### 問題3: マージ競合のリスク

**状況**:
- すべてのPRが同じファイルを変更
- マージ順序が重要
- 順番を誤るとマージ競合

---

#### 問題4: レビュー負担の増加

**状況**:
- PR #6のサイズが約15,700字（全セクション）
- レビュー者の負担が累積的に増加

---

## ✅ 解決策: 新規追加部分のみをレビュー

### 基本方針

**原則**: **各PRでは新規追加部分のみをレビュー、既存部分（前のPRでレビュー済み）はレビュー対象外**

---

### 実践方法

#### 1. PR作成者の責任

**必須**:
- PRコメントに「新規追加部分」を明記
- 既存部分（前のPRと重複）を明示

**実践例**:
```markdown
## レビュー対象範囲の明確化

**新規追加部分**: セクション B のみ（約2,200字）

**既存部分**（前のPRでレビュー済み、レビュー対象外）:
- セクション A（約2,400字、PR #1でレビュー済み）

**レビュー依頼**:
- セクション B の内容を重点的にレビューしてください
- セクション A との接続は軽く確認してください（オプション）
```

---

#### 2. レビュー者の責任

**必須**:
- 新規追加部分のみをレビュー
- 既存部分は詳細レビュー不要

**オプション**:
- 全体の流れを軽く確認（セクション間の接続等）

**実践例**:
```
ファクトチェックAI: 「セクション B のみをレビューします」
ファクトチェックAI: （レビュー後）「セクション B について3点の指摘があります」
ファクトチェックAI: 「セクション A との接続は問題ありません」
```

---

#### 3. マージ方針

**基本**:
- PR番号順でマージ（#1 → #2 → #3 → ...）

**必要に応じて**:
- マージ前に各ブランチをmainにリベース
- マージ競合を最小化

---

## 📊 効果の実測値

### トークン消費の削減

**Before（全体をレビュー）**:
```
PR #1: セクション A（約2,400字）
PR #2: セクション A + B（約4,600字）
PR #3: セクション A + B + C（約6,900字）
PR #4: セクション A-D（約9,500字）
PR #5: セクション A-E（約13,200字）
PR #6: セクション A-F（約15,700字）

合計: 約48,600字
```

**After（新規追加部分のみレビュー）**:
```
PR #1: セクション A（約2,400字）
PR #2: セクション B のみ（約2,200字）
PR #3: セクション C のみ（約2,300字）
PR #4: セクション D のみ（約2,600字）
PR #5: セクション E のみ（約3,700字）
PR #6: セクション F のみ（約2,500字）

合計: 約14,000字（実際のファイルサイズとほぼ同じ）
```

**削減効果**:
- 削減量: 約34,600字
- 削減率: 71%

---

### レビューの一貫性

**Before**: 同じセクションを複数回レビュー → 矛盾した指摘の可能性

**After**: 各セクションは1回のみレビュー → 一貫したレビュー

---

### レートリミット制約の緩和

**Before**: ファクトチェックAIが全PRで全体をレビュー → 早期にレートリミット到達

**After**: ファクトチェックAIは新規部分のみレビュー → レートリミット到達の遅延

---

## 🛠️ 実践ガイド

### PR作成時のチェックリスト

- [ ] 新規追加部分を明記
- [ ] 既存部分（レビュー済み）を明示
- [ ] レビュー範囲を明確化
- [ ] 前のPR番号を記載

### レビュー時のチェックリスト

- [ ] レビュー範囲を確認（新規追加部分のみ）
- [ ] 既存部分は詳細レビューしない
- [ ] 全体の流れを軽く確認（オプション）
- [ ] レビューコメントに対象セクションを明記

### マージ時のチェックリスト

- [ ] PR番号順でマージ
- [ ] マージ競合がないか確認
- [ ] 必要に応じてリベース

## 📊 適用場面

### 1. 大規模ファイルの段階的開発

**状況**: 10,000字以上のファイルを複数のセクションに分割して執筆

**適用**:
- 各セクションを個別のPRとして作成
- 新規追加部分のみをレビュー
- トークン消費の最適化

---

### 2. 複数章の並行執筆

**状況**: 複数の章を並行して執筆

**適用**:
- 各章を個別のファイル・PRとして管理
- 相互参照が必要な場合のみ、全体の流れを確認

---

### 3. コードファイルの段階的な機能追加

**状況**: 1つのコードファイルに複数の機能を段階的に追加

**適用**:
- 各機能を個別のPRとして作成
- 新規追加の機能のみをレビュー
- 既存機能は詳細レビュー不要

## 🎓 まとめ

**並行PR戦略の3原則**:
1. **新規追加部分のみレビュー**: 既存部分（レビュー済み）は対象外
2. **レビュー範囲の明確化**: PR作成者が新規部分を明記
3. **PR番号順でマージ**: マージ競合を最小化

**適用タイミング**:
- 大規模ファイルの段階的開発
- 複数セクション・章の並行執筆
- コードファイルの段階的な機能追加

**期待効果**:
- トークン消費の最適化（71%削減の実績）
- レビューの一貫性
- レートリミット制約の緩和
- 執筆速度の維持
