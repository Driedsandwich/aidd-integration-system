# GitHub記録の完全性確保

**最終更新**: 2025-10-19  
**出典**: 大規模プロジェクトで実証済みの実践知  
**適用範囲**: GitHub中心の大規模プロジェクト、特に複数AIでの協調作業

---

## 📋 概要

本文書は、**GitHub上での記録の完全性を確保し、トレーサビリティを維持するための実践的手法**をまとめたものです。

**背景**:
- 大規模プロジェクトで実証（数万字規模）
- 複数のAIによる協調作業（複数AIでの情報共有が必須）
- 記録漏れの発生→即座に対処→再発防止策の確立

**効果**:
- 詳細分析のGitHub記録による高いトレーサビリティ
- 複数AIでの効率的な情報共有
- 記録漏れの徹底防止

---

## 🎯 基本原則

### 原則: **サマリーだけでなく、詳細分析もGitHubに記録する**

**問題**（記録漏れの典型例）:
```
チャット内での詳細分析:
「Xタスクをカテゴリ分類しました:
 - カテゴリA: Y件（理由: ...）
 - カテゴリB: Z件（理由: ...）
 - ...」

GitHub記録:
「Xタスクを精査しました。完了です。」
```

**影響**:
- 他のAIが詳細な分析結果を参照できない
- トレーサビリティの喪失
- 判断の根拠が不明

---

## 📋 記録すべき内容

### 必須項目

1. **サマリー**:
   - 何を実施したか
   - 結果の概要

2. **詳細分析結果**:
   - カテゴリ分類
   - 項目数
   - 判定理由・根拠

3. **検証方法・判定基準**:
   - どのように確認したか
   - どのような基準で判定したか

4. **ユーザー確認待ち事項**（該当する場合）:
   - 選択肢（A案、B案等）
   - 推奨案
   - 推奨理由

5. **表形式等での視認性確保**:
   - テーブル、リスト等で見やすく整理

---

## ✅ 記録チェックリスト

**作業完了後、GitHub記録前に必ず確認**:

- [ ] サマリーを記録した
- [ ] 詳細分析結果を記録した（カテゴリ分類、項目数等）
- [ ] 検証方法・判定基準を明記した
- [ ] ユーザー確認待ち事項は詳細を記載した（選択肢、推奨案、理由）
- [ ] すべて事実ベース（推測・憶測ゼロ）
- [ ] 表形式等で視認性を確保した

---

## 🔄 標準フロー

```
1. 作業実施（精査・分析）
   ↓
2. チャット内で詳細報告
   ↓
3. GitHub記録チェックリスト確認 ← 重要
   ↓
4. GitHub記録（詳細分析含む）
   ↓
5. 記録完了確認
```

## 💥 失敗事例と対処法

### 失敗事例: 分析・精査作業の記録漏れ

**状況**:
- 残存タスクの精査を実施（複数のタスクを複数カテゴリに分類）
- チャット内では詳細な分析を報告
- しかし、GitHub記録はサマリーのみ

**問題**:
- 詳細分析（カテゴリ分類、項目数、判定理由）がGitHub上に記録されていない
- 他のAIがこの分析結果を参照できない
- トレーサビリティの喪失

**影響**:
- 将来、同様の精査を再度実施する必要
- 判断の根拠が不明
- 複数AIでの協調作業の効率低下

**対処**:
1. **即座に詳細分析をGitHub記録**
2. **記録チェックリストの確立**（6項目のチェックリスト）
3. **標準フローの確立**

**再発防止**:
- ✅ 精査・分析作業後は必ず詳細をGitHub記録
- ✅ チェックリストで記録の完全性を確認
- ✅ サマリーだけで済ませない

## 🛠️ 実践ガイド

### 記録対象となる作業

- 残存タスク・中断要素の精査
- Issue/PRの一括精査
- 数値検証・実測作業
- ユーザー確認待ち事項の整理

**判断基準**: 分析・精査作業はすべてGitHub記録の対象

---

### 記録のベストプラクティス

**❌ 悪い例**（サマリーのみ）:
```markdown
## 進捗報告

残存タスクを精査しました。問題ありません。
```

**✅ 良い例**（詳細分析を含む）:
```markdown
## 進捗報告

### 実施内容

残存タスクX件を精査しました。

### 詳細分析結果

| カテゴリ | 件数 | タスクID | 判定 |
|:---|:---:|:---|:---|
| 完了済み | Y件 | A, B, C... | すべて実施確認済み |
| 進行中 | Z件 | D, E... | 継続実施中 |
...

### 検証方法

- 各タスクのステータスを確認
- コミット履歴との照合

### ユーザー確認待ち事項

- タスクX: A案（推奨）vs B案、理由: ...
```

- 他のAIが参照できない
- トレーサビリティの低下

### After（記録の完全性確保）

- 詳細分析もGitHub記録
- 高いトレーサビリティ
- 複数AIでの効率的な情報共有
- 将来の参照が容易

## 🎓 まとめ

**GitHub記録の完全性確保の3原則**:
1. **サマリー + 詳細**: サマリーだけでなく、詳細分析もGitHub記録
2. **チェックリスト**: 記録前に6項目のチェックリストを確認
3. **標準フロー**: 作業→報告→チェック→記録→確認

**対象作業**:
- 精査・分析作業
- ユーザー確認待ち事項の整理

**期待効果**:
- 高いトレーサビリティ
- 複数AIでの効率的な情報共有
- 記録漏れの徹底防止
- 将来の参照が容易
