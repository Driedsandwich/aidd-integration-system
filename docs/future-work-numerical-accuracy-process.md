# 今後の作業でのパーセンテージ表現確認プロセス

**最終更新**: 2025-10-22  
**適用範囲**: 全プロジェクト、全リポジトリ  
**目的**: 今後の作業でパーセンテージ表現のハルシネーションを防止

---

## 📋 概要

本文書は、**今後の作業で作成済み資料を確認した際に、修正が必要であれば修正を実行する**ためのプロセスを定義したものです。

**背景**:
- 過去に作成済みの資料から根拠のないパーセンテージ記載が発見
- 今後の作業での継続的な監視が必要
- ハルシネーション回避の徹底

**効果**:
- 今後の作業での数値誤りの防止
- 既存資料の継続的な品質向上
- ハルシネーション回避の徹底

---

## 🔍 確認プロセス

### 1. 作業開始時の確認

**確認対象**:
- 作業対象のファイル
- 関連するドキュメント
- 参照する資料

**確認方法**:
```bash
# パーセンテージ表現の検索
grep -r "%" . --include="*.md" --include="*.txt" --include="*.py" --include="*.js" --include="*.ts"

# 具体的な数値の検索
grep -r "100%\|95%\|90%\|80%\|70%\|60%\|50%\|40%\|30%\|20%\|10%\|5%" . --include="*.md"
```

**確認項目**:
- [ ] パーセンテージ表現の存在
- [ ] 根拠の明記
- [ ] 測定方法の明確性
- [ ] 推定値と実測値の区別

### 2. 作業中の確認

**確認タイミング**:
- 数値を記載する前
- パーセンテージを使用する前
- 統計値を報告する前

**確認項目**:
- [ ] 数値の根拠を確認した
- [ ] 測定方法が明確である
- [ ] 測定時点を記録した
- [ ] 推定値か実測値かを区別した
- [ ] 第三者による検証が可能である

### 3. 作業終了時の確認

**確認対象**:
- 作成・修正したファイル
- 参照した資料
- 報告した数値

**確認項目**:
- [ ] 適切な表現パターンを使用した
- [ ] 根拠を明記した
- [ ] 測定条件を記載した
- [ ] 不確実性を適切に表現した
- [ ] ハルシネーションリスクを評価した
- [ ] 数値の妥当性を確認した
- [ ] 誤解を招く表現がないか確認した

---

## 🛠️ 修正プロセス

### 1. 不適切な表現の検出

**検出基準**:
1. 根拠となるデータがない
2. 測定方法が不明確
3. 比較対象が不明
4. 推定値を断定的に表現

**検出方法**:
- コードベース検索
- 手動確認
- 第三者による検証

### 2. 修正方針の決定

**即座修正**:
- 根拠のない断定的表現
- 測定方法が不明確な表現
- 推定値の断定的表現

**後回し**:
- 統計学の標準的な基準値
- 実測値に基づく計算結果
- 明確な根拠がある表現

### 3. 修正の実行

**修正手順**:
1. 不適切な表現の特定
2. 適切な表現パターンの選択
3. 修正の実行
4. 修正内容の記録
5. 関連Issueへの報告

## 🎯 まとめ

今後の作業でのパーセンテージ表現確認プロセスにより、継続的に数値情報のハルシネーションを回避できます。

**重要なポイント**:
1. **作業開始時の確認**: 対象ファイルのパーセンテージ表現をチェック
2. **作業中の確認**: 数値記載前の必須確認項目
3. **作業終了時の確認**: 作成・修正したファイルの最終確認
4. **継続的な監視**: 定期的な監査と新たな失敗事例の記録
5. **ルールの改善**: 継続的な改善と教育・啓発

**継続的な改善**:
- 失敗事例の記録と学習
- チェックリストの活用
- 自己検証プロセスの確立
- ハルシネーションリスクの評価

このプロセスを活用することで、今後の作業で数値情報の信頼性を確保し、ハルシネーションを回避できます。
