# 両リポジトリ共通のパーセンテージ表現対応策

**最終更新**: 2025-10-22  
**適用範囲**: aidd-integration-system、master-thesis-2025  
**目的**: パーセンテージ表現のハルシネーション回避の統一対応

---

## 📋 概要

本文書は、**aidd-integration-system**と**master-thesis-2025**の両リポジトリにおいて、パーセンテージ表現のハルシネーション（AIによる数値の捏造・誤生成）を回避するための統一的な対応策をまとめたものです。

**背景**:
- 両リポジトリで同様のパーセンテージ表現ハルシネーションが発見
- 根拠のない数値の断定的表現
- 信頼性の基盤となる数値の正確性の重要性

**効果**:
- 両リポジトリでの一貫した数値誤り防止
- 推定値と実測値の明確な区別
- データの正確性とトレーサビリティの確保

---

## 🎯 共通基本原則

### 1. 数値情報の特別扱い

**原則**: **数値は信頼性の基盤**

**実践**:
- ✅ すべての数値は実測値を使用
- ✅ 推定値は「推定」「目標」「期待」等の表現を使用
- ✅ 根拠の明記を義務化
- ✅ 測定可能性の事前確認

**絶対禁止**:
- ❌ 推測で数値を記載（「約500件」「おそらく30ファイル」等）
- ❌ 概算で済ませる
- ❌ 過去の記憶に頼る
- ❌ 根拠のないパーセンテージ表現

---

### 2. パーセンテージ表現の統一ガイドライン

#### 適切な表現パターン（両リポジトリ共通）

**1. 実装完了**
```
✅ マルチデバイス対応: 100%達成（実装完了）
✅ ツール移行対応: 100%達成（移行ガイド作成完了）
✅ 基盤整備: ✅ 完了（実装完了）
```

**2. 目標値**
```
✅ 同期成功率: 目標95%以上（実装後測定予定）
✅ 品質スコア: 目標90%以上（運用開始後測定）
```

**3. 期待値**
```
✅ フィードバック収集の自動化により大幅な改善が期待される
✅ 開発効率の向上が期待される
✅ 把握度向上: 大幅な改善（実測値に基づく）
```

**4. デモ結果**
```
✅ 統合スコア: 100.0%（デモ環境での実証結果）
✅ 処理速度: 43,344.5サイクル/分（デモ環境での測定）
```

**5. 推定値（根拠明記必須）**
```
✅ 推定○○%（根拠: ○○の研究結果）
✅ 予想○○%（根拠: 類似システムの実績）
```

#### 不適切な表現パターン（両リポジトリ共通）

**❌ 根拠のない断定的表現**
```
❌ フィードバック収集率: 5-10% → 60-80%
❌ 同期成功率: 95%以上
❌ 統合スコア: 100.0%（実装完了と混同）
❌ 把握度向上: 80% → 98% (+18%)
❌ 把握度: 98%
❌ GitHub同期: 569ファイル、100%追跡
```

**❌ 測定方法が不明確**
```
❌ 効率向上: 50%以上
❌ エラー削減: 80%以上
❌ 品質向上: 大幅に改善
```

## 🔍 共通検出・修正プロセス

### 1. 既存資料の網羅的チェック

**検索キーワード**:
```
パーセンテージ % 100% 95% 90% 80% 70% 60% 50% 40% 30% 20% 10% 5% 根拠 測定 実測
```

**検索対象ファイル**:
- README.md
- ドキュメント（.md）
- コード（.py, .js, .ts）
- 設定ファイル（.json, .yaml）

### 2. 不適切な表現の特定

**判定基準**:
1. 根拠となるデータがない
2. 測定方法が不明確
3. 比較対象が不明
4. 推定値を断定的に表現

### 3. 修正方針

**即座修正**:
- 根拠のない断定的表現 → 適切な表現パターンに置換
- 測定方法が不明確 → 根拠を明記
- 推定値の断定的表現 → 「推定」「目標」「期待」等の表現を使用

## 📊 共通失敗事例と学習

### 失敗事例 #1: フィードバック収集率の不適切な表現

**問題**: 「フィードバック収集率: 5-10% → 60-80%」
- 根拠となるデータなし
- 測定方法が不明確
- 比較対象が不明

**修正**: 「フィードバック収集の自動化により大幅な改善が期待される」

**学習**: 推定値を断定的に表現してはいけない

### 失敗事例 #2: 同期成功率の不適切な表現

**問題**: 「同期成功率: 95%以上」
- 目標値として設定されているが実測値なし
- 測定期間・条件が不明

**修正**: 「同期成功率: 目標95%以上（実装後測定予定）」

**学習**: 目標値と実測値を明確に区別する

### 失敗事例 #3: 把握度の不適切な表現

**問題**: 「把握度向上: 80% → 98% (+18%)」「把握度: 98%」
- 根拠となるデータなし
- 測定方法が不明確
- 比較対象が不明

**修正**: 「把握度向上: 大幅な改善（実測値に基づく）」「把握度: 高（実測値に基づく）」

**学習**: 主観的な評価を数値で表現してはいけない

## 🎯 まとめ

両リポジトリ共通のパーセンテージ表現対応策により、数値情報のハルシネーション回避が統一化されます。

**重要なポイント**:
1. **数値は特別扱い**: 特に厳格な基準を適用
2. **根拠の明記**: すべての数値に根拠を明記
3. **推定値と実測値の区別**: 明確に区別して表現
4. **自己検証の徹底**: 自分の生成した数値を疑う
5. **測定可能性の確保**: 第三者による検証が可能

**継続的な改善**:
- 失敗事例の記録と学習
- チェックリストの活用
- 自己検証プロセスの確立
- ハルシネーションリスクの評価

この対応策を活用することで、両リポジトリで数値情報の信頼性を確保し、ハルシネーションを回避できます。
